# DESIGN — salarymen v0.1

## Goal statement

Vague prompt → working, deployed, verified product in minutes (scaffold) and a
continuously improving one over days (loop). Self-hosted. For people who can't
prompt like seniors.

## Non-goals for v0.1

- Multi-stack matrix (one template only: next-tailwind-sqlite)
- Multi-driver matrix (claude-code first; driver interface abstracted but one impl)
- Web dashboard UI (BOARD.md + GitHub Projects sync is the v0.1 view)
- Team/multi-user

## Architecture

```
salarymen/            python package (stdlib + httpx only)
  cli.py              init | tick <lane> | status | board
  config.py           salaryman.yml loader (layer merge)
  board.py            BOARD.md parse/write (the kanban is data)
  lanes/
    intake.py         INBOX -> TODO decomposition (LLM call w/ provenance)
    builder.py        TODO -> DOING -> PR/commit (driver invocation)
    critic.py         live probe + screenshot + vision judge -> evidence
    auditor.py        board vs git/tests reconciliation
  drivers/
    base.py           Driver interface: run(task_brief) -> result+artifacts
    claude_code.py    subprocess claude-code --print (first)
    pi.py             pi --print (second; RAM-cheap)
  evidence/
    screenshots/      per-card pngs
    probes.jsonl      HTTP probe log
templates/
  next-tailwind-sqlite/   the ONE opinionated scaffold (copier template)
web/                  later: read-only board viewer (v0.2)
```

## Key flows

### init (minutes)
1. `salarymen init my-app` → copy template, render salaryman.yml
2. intake runs once on the user's opening prompt → seeds BOARD.md
3. builder tick(s) implement the "walking skeleton" cards
4. critic verifies → `salarymen deploy` (vercel token in env) → LIVE URL printed

### tick loop (forever)
cron calls `salarymen tick <lane>`. Each lane = one phase, then exit.
Wake-gates before any LLM call: disk/RAM/quota checks; `--wake false` exits 0
silently (zero tokens when idle).

### Evidence contract
A DONE card without an evidence block is reopened by the auditor. Evidence =
{screenshots[], probe_results[], vision_verdict?}. This is the anti-slop core.

## The backfill problem (why intake exists)

Today the owner manually prompts agents and pastes tasks into TASKS.md. In
salarymen, ALL prompts land in INBOX verbatim; intake decomposes them into
cards with `from:` provenance. Feature docs (`docs/features/<id>.md`) are
generated by the auditor from merged card history — nobody writes them by hand.

## Composition model (dsh/Cordis lesson)

Registration-based plugin systems rot (registry drift, ordering surprises).
Salarymen uses **layered config composition**: defaults < salaryman.yml <
local override < CLI patch. Engine swaps (sqlite→postgres) are config edits +
a migration lane run, never code edits.
